# 竞品价格雷达 · 工作台（Edge / Chrome MV3 扩展）

> v2.1.0：新增「波动」看板（每个 SKU 的累计变动 / 波动率 / 回撤，以及按尺寸段、系统、品牌、类型
> 聚合的市场趋势）；新增「确认本次采集」——确认后当前价成为下一轮基准价。v2.0 的分析视图、
> 价格带、同尺寸对标、2–4 个 SKU 对比继续保留。

按内置竞品清单逐个打开电商平台商品页，**只读商品主价格区**取「到手价」，记录价格历史、对比基准价、
生成降价 / 涨价 / 历史新低 / 采集异常提醒。数据只存本机。

> 完整设计说明、取价规则和验证结果见上级目录 `README.md`。

## 一、安装

1. Edge 地址栏打开 `edge://extensions/`；
2. 打开左下角「开发人员模式」；
3. 点「加载解压缩的扩展」，选择本文件夹（`...\竞品价格雷达\extension`）；
4. 把「竞品价格雷达」固定到工具栏；点图标打开工作台。

> 更换文件夹路径会换扩展 ID（等于新存储）。换路径前先在旧版「导出 JSON」，新版「导入备份」。

## 二、使用流程

1. **确认清单**：首次打开自动加载 `data/competitor-skus.json`（176 个竞品 SKU，来自月度竞品 Excel）；
2. **登录电商平台**：工作台弹出后，在 Edge 登录要采价的电商平台账号；
3. **先试跑**：设置 → 每次最多采集改成 10，间隔 3–6 秒；
4. **开始采集**：监控清单 → 选「当前筛选 / 全部 / 仅勾选」→ 开始采集；
   - 后台标签页：不弹窗，可继续用电脑；
   - 前台窗口 + AI：弹小窗，开启 AI 后对价格区域做截图复核（截图只在内存，不保存）；
   - 「重新核验」：忽略“跳过今天已采集”，把当前范围再采一遍；已下架行仍然跳过，
     用来修正之前版本误采到的数字；
5. **确认基准**：采完点采集条上的 **「确认本次采集」**（或详情里的「确认当前价为下期基准」），
   当前价才会滚成下一轮基准；不点则一直沿用上次确认价 / 导入价；最新价下会标「待确认 / 已确认」；
6. **核对**：表格行点开详情抽屉，对照页面大号红字到手价；低置信度会标「待核对」；
7. **看分析**：左侧「分析」看价格带分布、品牌均价、尺寸 × 品牌热力图、各尺寸价格锚点；
   点热力图单元格可跳回清单筛选；勾选 2–4 个 SKU 可点「对比」看归一化走势；
8. **看波动**：左侧「波动」看每个 SKU 的累计变动 / 波动率 / 最大回撤，以及按尺寸段、系统、品牌、
   类型聚合的市场趋势、分组波动和上涨 / 下跌数量；
9. **看异动**：总览的数字卡片可点筛选；异动中心处理 / 忽略提醒；
10. **跟进 / 备份**：详情里可改基准价、写备注、复制 SKU、打开商品页；侧栏「导出 JSON」备份。

## 三、取价口径

- 默认取**到手价**（竞品实际成交价）；设置里可改成电商平台价优先 / PLUS 会员价优先；
- 只在主价格区里取，自动排除跨平台比价卡片、关联购买、推荐、广告、榜单、足迹等模块；
- 只认可见元素；拼接被拆开的数字；拒绝 56 / .56 / 5折 / 满5000减500；
- 连续 3 次读数一致才算稳定，之后复核页面二次刷新后的最终价；
- 取不到就记录失败，不会「猜一个看起来合理的价格」；
- 下架商品会尽量自动识别：标签页被跳回电商平台首页 / 商品频道首页、页面标题或正文出现
  「该商品已下架 / 商品不存在 / 页面不存在」、商品 URL 下只剩电商平台通用空页，都会判为「已下架」，
  写入本地下架标记并在后续批量采集中跳过；详情抽屉可手动「标记已下架 / 恢复上架」；
- 「已售罄 / 暂时无货 / 暂无报价」标为「不可售」，不会混成已下架；
- 应用层再按基准价做合理性校验，页面 SKU 与任务不一致也会记失败。

## 四、设置说明

| 设置 | 默认 | 说明 |
|---|---|---|
| 默认轨道 | 后台标签页 | 前台窗口 + AI 会抢焦点 |
| 取价口径 | 到手价优先 | 也可选电商平台价 / PLUS 价 |
| 每次最多采集 | 40 | 0 = 全部 |
| 页面间隔 | 3–6 秒 | 低频使用 |
| 跳过今天已采集 | 开 | 重采单条不受影响 |
| 较基准价偏离 | 5% | 超过生成降价/涨价提醒 |
| 大幅异动 | 15% | 超过标记「紧急」 |
| 较上次采集变动 | 3% | 基准没触发时才看这个 |
| 历史新低 / 采集异常提醒 | 开 | 可关 |
| 预览悬停延迟 | 900ms | 眼睛图标悬停多久弹小窗 |
| AI | 关 | 可选；OpenAI 兼容接口，Key 只存本机 |

## 五、数据与安全

- 只读页面 DOM，不点击、不提交订单、不调用电商平台接口；
- 数据保存在 `chrome.storage.local`（`priceradar.db.v1` / `priceradar.meta.v1`），不上传；
- 截图不落盘；启用 AI 时，裁剪后的价格小图会发送到你配置的 AI 接口（默认关闭）；
- 导出的 JSON 备份不包含 AI Key；
- 低频、分批、可暂停；出现安全验证自动暂停，请休息后再试；
- 在 `edge://extensions/` 里「移除」扩展会清空本地数据；更新代码请只点「重新加载」。

## 六、常见问题

| 现象 | 处理 |
|---|---|
| 价格不对 | 设置 → 调试 → 复制最近一次取价 JSON，查看候选价格、字号、主价格区标记 |
| 一直超时 | 确认登录、能打开商品页；降低每批数量、加大间隔 |
| 某个 SKU 采不到 | 确认 SKU 是电商平台商品编号；在详情里点「立即采集」单跑一次 |
| 商品已下架但没识别 | 详情抽屉点「标记已下架」，后续批量采集会跳过；如果又上架了点「恢复上架」 |
| 之前采到过错的数字 | 点采集条上的「重新核验」重跑一遍当前范围（已下架行会跳过），或先清空采集记录再跑 |
| 基准价不对 | 详情 → 基准价 → 手动 / 用导入价 / 用最新价 / 恢复自动 |
| 异动太多 | 调大「较基准价偏离 / 较上次采集变动」；或忽略单条 |
| 数据迁移 | 旧机「导出 JSON」→ 新机「导入备份」 |
