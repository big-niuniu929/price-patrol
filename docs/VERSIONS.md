# 版本线

仓库不是一次成型，而是按真实迭代顺序提交的。每个提交对应一段可运行的状态，tag 指过去就能看当时的代码。

| tag | 时间 | 形态 | 为什么会有这一版 |
|---|---|---|---|
| `v0.1-patrol` | 2026-10 下旬 | 巡检插件（单轨） | 业务上每天要手工抄几十个 SKU 的挂网价。第一版只做一件事：按基表逐条打开商品页、把价格抄回来、导出回填 Excel |
| `v0.2-dual` | 2026-11 初 | 巡检插件 · 双轨 | 页内取价会被改版和登录态影响。加一条官方 API 桥（`api_bridge.py`），两条路径取同一个 SKU 的价，对不上就复核 |
| `v0.3-matrix` | 2026-11 中 | 巡检插件 · 矩阵 | 双轨之后读数变多，需要「矩阵视图」把同一 SKU 的多来源读数并排看，异常值才看得出来 |
| `v0.4-share` | 2026-11-05 | 市占率扩展 v2.1.7 | 另一条支线：从「抄价格」到「算份额」。把处理链拆成 `lib/pipeline.js` / `rules.js` / `store-schema.js`，接入 xlsx 读写与列映射，写了自己的 QA 套件与 CDP 截图工具 |
| `v1.1.5-3in1` | 2026-11-10 起，11-17 收尾 | 三合一平台 | 三个独立插件各自有取价逻辑，改一处要改三遍。合并成一个扩展 + 平台壳；把 15 个 mock 商品页场景拿来对三套引擎逐字段比对，统一到同一基准 |

## 一次真实的迭代长什么样

`v1.1.5` 之间的小版本说明了这类工具的真实成本：

- **v1.1.0**：巡检业务整包升级到 v1.3.4（内置基表 153 行 / 146 行有 SKU，新增基表自动升级与差异提示），三个业务取价统一到巡检基准，修掉竞品的 `saveMeta()` 写后校验 bug（`JSON.stringify` 比较对象被 chrome.storage 重排键顺序 → 永远误报失败）
- **v1.1.1**：商品详情页改版，竞品引擎还在找旧结构（`.summary-price` / `.p-price` / `#price` 全部不存在）；旧黑名单关键词 `floor` 把新版价格面板整块排除；「已下架」字样被误判成整页下架。三处都修了，并用真实页面 DOM 回放验证
- **v1.1.2**：竞品监控加「导出最新数据」（当前筛选结果 → CSV），验收 52/52

这些细节在 `docs/RELEASE-1.1.5.md` 里有原文。

## 怎么看历史

```bash
git log --oneline --decorate --all     # 5 个提交 + tag
git show v0.2-dual --stat              # 这一版多了哪些文件
git checkout v0.4-share                # 切过去跑
git checkout v1.1.5-3in1               # 回最新
```

GitHub 上也能直接看：点仓库的 **Tags** 或 **Commits**，每个 tag 都指向一个完整可运行的树。
