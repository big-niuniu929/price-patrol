# 价格监控平台（Edge / Chrome MV3 扩展 v1.0.0）

一个入口，三条业务：**价格巡检（双轨版）**、**市场占有率**、**竞品价格监控（竞品价格雷达）**。
点扩展图标进入平台后**先选择业务**，选定后的界面与原插件完全一致；三个业务的数据彼此独立，只保存在本机浏览器。

> 本目录是三个已有插件的合并版。三个原插件目录（`巡检\巡检插件-双轨版`、`市占率`、`竞品数据监控\竞品价格雷达`）**未做任何修改**，
> 合并所需的全部改动都发生在本目录的副本里（改动清单见第四节）。

---

## 一、安装

1. 浏览器地址栏打开 `edge://extensions/`（Chrome 为 `chrome://extensions/`）；
2. 打开左下角「开发人员模式」；
3. 点「加载解压缩的扩展」，选择**本目录**（即包含 `manifest.json` 的 `价格监控平台` 文件夹）；
4. 把「价格监控平台」固定到工具栏，点图标打开平台页。

> 扩展 ID 与目录路径绑定：换路径/重装 = 新存储（旧数据不会自动带过来）。迁移方法见第五节。

## 二、使用流程

1. **进入平台**：默认停在「选择业务」页，三张业务卡片；可按 `1` `2` `3` 直接进入，上次用过的业务会带「上次使用」标记；
2. **进入业务**：点卡片 → 顶部出现一条细导航条，下面用 iframe 装载该业务的原界面（表格、看板、抽屉、设置都跟原来一样）；
3. **切换业务**：细导航条中间的三个按钮直接切；左侧「价格监控平台」或右侧「业务选择」回到首页（也可按 `Esc`）；
4. **独立打开**：右上角「独立打开」把当前业务单独开成一个标签页——打开的是**该业务的原生页面**
   （`modules/<业务>/app.html`，不带平台导航条），适合长时间采集：**在平台里切换业务会卸载当前业务的页面，
   正在跑的采集会中断**，所以跑几十上百个 SKU 时建议用「独立打开」；
5. 各业务内部操作与原插件说明一致（见第三节的对应文档）。

## 四、合并方式（做了什么、没做什么）

**没改业务逻辑。** 三个业务的页面文件原样放在 `modules/patrol`、`modules/share`、`modules/radar`，
平台页用 `iframe` 装载，所以界面、交互、数据结构与原来逐像素一致。

只做了两类必要的副本改动（原始插件目录未动）：

1. **资源路径**：模块内 `chrome.runtime.getURL('data/...')` 改为 `chrome.runtime.getURL('modules/<业务>/data/...')`，
   因为合并后 `data/` 不在扩展根目录了；
2. **消息命名空间**：三个商品页取价脚本原来都向扩展发 `ITEM_PRICE_RESULT`、都响应 `PING`，
   合并后同在 `item.shop.example.com` 上运行会互相串消息，因此按业务加前缀：
   `PATROL_ITEM_PRICE_RESULT` / `RADAR_ITEM_PRICE_RESULT`、`PATROL_PING` / `SHARE_PING` / `RADAR_PING`
   （`PREVIEW_CAPTURE` 本来就是市占率独有，未改）。

其他说明：

- 三个 `content.js` 仍各自注入 `item.shop.example.com`（每份都有独立防重入标记，互不干扰）；
  **价格巡检的取价逻辑（v2.1）是基准**：市占率与竞品监控的取价引擎在 v1.1.0 里已按巡检 v2.1 的规则逐条对齐
  （到手价 / 电商平台价 / PLUS 价选择、跨平台比价与关联购买等模块排除、隐藏元素与首屏判定、数字片段与折扣文案拒绝、
  连续 3 次稳定 + 二次刷新复核、不猜价），并保留各自额外能力（市占率：尺寸/型号/套餐/品牌提取；竞品：置信度/页面状态/下架识别）；
- 平台页里的 iframe 用 `location.replace()` 导航（不是直接改 `src`），这样业务切换不会往浏览器历史里塞 iframe 记录，
  按「后退」会正常回到上一个业务、再退回到平台首页（而不是退到空白页）；
- 巡检「完整版」自带 `modules/patrol/data/preset-settings.json`（采集节奏 / 巡检范围 / AI 等偏好预置），
  首次安装时自动预置；已有本地设置则不会被覆盖；
- 原插件的 `manifest.json` / `background.js` 不复制，由平台根目录的 `manifest.json` / `background.js` 统一管理
  （权限取三者并集：`storage`、`tabs`、`unlimitedStorage`、`clipboardWrite` + 电商平台商品页 / 本机 API 桥 / token 域）；
- 价格巡检的「官方API采集」仍走本机桥 `http://127.0.0.1:18765/`：桥的启动方式不变，
  在 `巡检插件-双轨版` 目录里运行 `启动API桥.py` / `启动API桥.bat` 即可，行情数据与账号配置（`accounts.local.json`）仍在原目录；
- 首页只做入口与导航，不读写任何业务数据，也不向电商平台页面注入任何 UI。

## 五、数据与迁移

新扩展 = 新扩展 ID = 全新的 `chrome.storage.local`，**旧插件里的数据不会自动出现**。要带走历史数据的做法：

| 业务 | 旧插件 | 新平台 |
|---|---|---|
| 价格巡检 | 工作台「导出 JSON」（完整数据）+「导出基表 JSON」 | 价格巡检业务 →「导入数据」/「导入基表」 |
| 市场占有率 | 「导出 → 导出 JSON」（备份） | 市场占有率业务 →「导入备份」 |
| 竞品监控 | 侧栏「导出 JSON」（备份） | 竞品监控业务 →「导入备份」 |

- AI 复核的 API Key **不会**出现在导出的 JSON 里，需在对应业务的「设置」里重新填写；
- 三个业务的数据键互不相同，切换业务不会互相覆盖；
- 平台首页记住的「上次使用业务」只是页面偏好（`localStorage`），与业务数据无关。

## 八、合规与风控

- 只在手动点击后工作；只读页面 DOM，不点击、不提交订单、不调用电商平台接口、不绕过验证；
- 低频、分批、可暂停；出现「页面要求安全验证」立即停止，休息后再试；
- 建议使用专用采集账号；
- 所有数据只存本机 `chrome.storage.local`，不上传任何服务器（业务里自带 AI 复核时，按原插件说明只把价格小图发到你配置的接口）。

## 九、常见问题

| 现象 | 处理 |
|---|---|
| 点图标没反应 / 平台页打不开 | `edge://extensions/` 确认已启用并「重新加载」；扩展目录内不能有 `_` 开头的文件/文件夹（浏览器限制） |
| 装好新平台后，原来的三个插件要不要留 | **建议先在旧插件里「导出」数据，再在 `edge://extensions/` 禁用或移除旧插件**：否则同一个电商平台商品页会同时被旧插件和新平台的取价脚本重复扫描（消息互不串，但会白白多跑几套采集、也更容易触发风控） |
| 某个业务界面空白 | 先用右上角「独立打开」验证该业务单页是否正常；再按 F12 看 Console 报错（把报错截图发给维护人） |
| 竞品最新价格怎么导给同事 | 竞品监控 →「监控清单」右上角「**导出最新数据**」（按当前筛选导出 CSV，Excel 直接打开）；侧栏「导出 CSV」是整份清单，「导出 JSON」是完整备份 |
| 怎么让下一轮「较基准」以上一轮为准 | 采完点「**写入记录表**」（批量，按钮上显示待写入个数），本批最新价一次性写入记录表；之后「较基准」= 相对记录表里的价格。点「记录表」可查看/导出/清空 |
| 切换业务后正在跑的采集停了 | 平台里切业务会卸载业务页面；长任务请用「独立打开」在独立标签页里跑 |
| 数据看起来是空的 | 新扩展是空存储，按第五节从旧插件导出 → 导入 |
| 价格巡检「官方API 未连接」 | 先在 `巡检插件-双轨版` 目录启动 API 桥（`启动API桥.py`）；v1.3.4 起支持多供应商账号，需要配套的新版 `api_bridge.py`（在 `巡检插件-双轨版-完整版-20261110.zip` 里），旧桥没有 `/api/accounts` 接口时设置页会提示未连接 |
| 商品页采集一直超时 | 确认已登录电商平台、能正常打开商品页；把「每次最多采集」调小、间隔调大后试跑 |
| 换电脑/换路径后数据没了 | 扩展 ID 变了；用「导出 JSON」→「导入备份」迁移 |
