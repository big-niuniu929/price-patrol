# 市占率报表加工程序第一阶段计划

## Goal

建立一个可在 Windows 和 macOS 上运行、后续可迁移为飞书小程序后端能力的基础工具，完成：

1. 读取一个或多个平台导出的榜单文件。
2. 读取匹配库中的全部店铺工作表。
3. 按 SKU 自动匹配尺寸段和价格段。
4. 自动识别并列出未匹配的新 SKU，支持人工补充匹配库。
5. 生成与当前“3C 配对表”相近的配对结果文件。

统计结果先实现当前月的品牌销售额/占比导出；历史趋势图等到用户补充历史数据后接入。

## Context and constraints

- SKU 是唯一匹配键，必须按文本处理，不能因 Excel 数字格式丢失精度或前导零。
- 匹配库的业务字段暂定为：SKU、尺寸段、价格段；商品名称和品牌仅作为展示或校验信息。
- 匹配库可以通过增加工作表或在已有工作表增加行来扩充店铺。
- 店铺名称可能不同，但可通过配置的关键词与榜单文件/工作表名称建立关系。
- `3C 配对表.xlsx` 只把“9月”作为历史参考模板，不读取其他工作表作为业务输入。
- 平台榜单字段应尽量原样保留，程序只新增或补充匹配字段。
- 每次基础流程处理一个店铺；用户上传榜单后在 UI 中选择对应店铺。
- 支持一次导入多个店铺榜单，并允许对每个榜单手动指定匹配库店铺，或根据文件名关键字自动建议。
- 配对结果按“9月”案例输出精简结构：商品编号、商品名称、品牌名称、尺寸段、价格段、成交金额。
- `成交金额`来自榜单原始“成交金额”区间的两个边界值，按 `(下限 + 上限) / 2` 计算。
- 匹配库以内置持久化数据为主，支持从 Excel 覆盖/合并导入，也支持导出；存在原始 Excel 路径时可兼容同步写回并先备份。
- 尺寸段、价格段使用“可选已有值 + 可自定义文本”的组合输入，减少新增 SKU 的录入成本。

## Decision

首版采用“本地可运行的数据处理核心 + Python HTTP 服务 + Edge 应用窗口”的结构。数据处理核心、匹配库数据层、批量处理和统计输出分离，未来可以复用核心逻辑作为飞书小程序后端/服务接口。首版不把业务规则写死在某个店铺名称或固定四个店铺上。

建议的内部数据结构：

- `MatchRecord`: `sku`, `store`, `size_band`, `price_band`
- `ReportRow`: 原始榜单字段 + `store`, `size_band`, `price_band`, `match_status`
- `StoreRule`: `store_name`, `keywords`, `source_sheet` 或自动识别信息

## Files or surfaces affected

- `src/`：匹配库读取、榜单读取、店铺识别、SKU 匹配、结果导出。
- `ui/` 或首版 UI 文件：文件选择、店铺/文件识别结果、未匹配 SKU 编辑、生成结果。
- `tests/`：SKU 文本化、重复 SKU、未匹配 SKU、新增店铺工作表、导出结果等边界测试。
- 原始桌面 Excel 文件只读，不覆盖。

## Ordered implementation steps

1. 确认店铺选择、输出列、输出文件命名和尺寸/价格段的补充方式。
2. 搭建数据处理核心和测试。
3. [进行中] 将 UI 拆分为工作台、批量处理、匹配库和统计结果页面；未匹配 SKU 使用可选/可自定义的组合输入。
4. [已完成] 实现配对表导出、匹配库备份和基础输入校验。
5. [已完成] 用当前 3C 样例数据完成核心读取、匹配、成交金额解析和导出冒烟验证。
6. [进行中] 支持内置匹配库的导入、合并、覆盖、修改和导出，并支持多榜单批量处理。
7. 根据 `统计结果.xlsx` 生成当前月按品类/店铺的品牌销售额、占比结果；历史数据到位后再增加趋势图。

## Verification

- 当前样例榜单 200 个 SKU 应全部匹配到“3C店”工作表。
- 匹配库空工作表不应导致程序报错或生成空店铺结果。
- 同一 SKU 在多个店铺表重复时应提示冲突，而不是静默覆盖。
- 新 SKU 应出现在待补充清单，并能在 UI 中填写尺寸段和价格段后重新生成结果。
- 输出结果不应依赖 `3C 配对表.xlsx` 的公式缓存。
- 当前 3C 样例已验证：200 条榜单记录全部匹配，第一条成交金额 `￥200万 ~ ￥400万` 输出为 `300`，结果表共 201 行（含表头）。
- 新 SKU 写回测试已通过，写回前会生成带时间戳的匹配库备份。
- UI 已改为参考“报表汇总APP”的本地 HTTP 服务形式，保留原有业务按钮和数据处理入口。
- 已修正双击启动器仍调用旧 Tk 界面的缺陷；启动器现在调用 `web_app.py`，依赖检查不再强制导入 Tk。
- 已补充浏览器表格单击选中、按钮编辑选中行、鼠标跟随高光和 `@property --angle` 流光边框。

## Risks and follow-ups

- 目前已确认一次处理一个店铺，并由用户选择店铺。
- 统计结果中的品牌金额与当前 3C 配对数据的直接中位值汇总不完全一致，可能存在人工修正、不同数据源或取数范围差异，需要后续确认。
- 价格段和尺寸段是自由文本还是固定枚举，需要在 UI 设计前确认。
- 飞书小程序通常需要云端存储和服务端接口；本地 UI 可先验证业务流程，正式迁移时再确定权限、多人同时编辑和版本管理。
- 需要使用 Playwright 完成桌面和移动视口的截图及交互回归；本地原生文件选择框不纳入自动点击流程，接口注入测试文件路径完成同等业务验证。
